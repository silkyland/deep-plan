## 7. Design decisions

### Decision 1: rule-backed line cap (closes gaps 1, 2)
- Decision: create `src/cart/DiscountCapRule.js`, CommonJS export `{ DiscountCapRule }`, extending named `{ RuleInterface }` from `../../vendor/rule-engine/RuleInterface`. Scope is `{ discountPercent, discountCapPercent }`; match checks percentage > cap, apply assigns percentage = cap and returns nothing. In `src/cart/PriceCalculator.js`, instantiate once, read cap fresh for each call through validateCap, then match/apply and use the resulting percentage in unchanged rounding. Preserve exports and cart delegation. Valid numeric line percentages only; preserve other existing line-input behavior.
- Reversibility: REVERSIBLE; owner confirmed.
- Rationale: shared pricing covers both paths and uses vendor contract (section 3).
- Rejected: cart-only enforcement misses direct calls; changing vendor is unnecessary.

### Decision 2: database persistence (closes gap 3)

- Reversibility: ONE-WAY, UNCONFIRMED.
- Rationale: admin form currently has no persistence.
- Rejected: retaining config literal does not save admin edits.
