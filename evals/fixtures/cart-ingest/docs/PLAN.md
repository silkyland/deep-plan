## 7. Design decisions

### Decision 1: enforce the cap via a rule-engine rule (closes gaps 1, 2)
- **Decision:** add a `DiscountCapRule` implementing `RuleInterface`.
- **Reversibility:** REVERSIBLE
- **Rationale:** the framework provides rules for this (`vendor/rule-engine/RuleInterface.js:16`).
- **Rejected:** inline `Math.min` — does not use the rule engine.

### Decision 2: persist the cap in the database (closes gap 1)
- **Decision:** move `discountCapPercent` from `src/cart/config.js` into a `settings` table.
- **Reversibility:** ONE-WAY, `UNCONFIRMED`
- **Rationale:** lets the admin form save it.
- **Rejected:** keep the config literal — the admin form could never change it.
