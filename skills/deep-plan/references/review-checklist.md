# Plan Acceptance Checklist

A plan is presentable only when **every** item is a YES. Grade honestly,
item by item (step 7a of [goldfish-gates.md](goldfish-gates.md)), before
spawning any goldfish. If an item fails, return to the phase in
[research-phases.md](research-phases.md) or [design-phases.md](design-phases.md)
that produces it — do not patch the wording.

## Contents

- Evidence
- Research depth
- Decisions
- Roadmap
- Verification
- Goldfish gates
- Rejection protocol

## Evidence

- [ ] Every bug/finding has a **file:line** citation — no floating descriptions.
- [ ] Every framework/API claim has a **vendor path** or a **versioned doc URL**.
- [ ] Zero framework facts sourced from training-data memory.
- [ ] Every remaining unknown is tagged **UNVERIFIED** with what would confirm it
      — nothing "probably" works.

## Research depth

- [ ] The **Corrections** section exists and has content — a plan that never
      found itself wrong did not explore for real. (If genuinely empty, it
      says why the research still qualifies as adversarial.)
- [ ] Every Phase 0 **Research Question** is answered with evidence or tagged
      UNVERIFIED — none silently dropped.
- [ ] Inventory classifies components as works / half-wired / dead, each with
      a proving file path.
- [ ] The write path AND the read path were both traced end to end.

## Decisions

- [ ] Every gap has **one committed decision with rationale** — no "A or B
      both fine" menus anywhere in the document.
- [ ] Rewrites (if any) are justified by evidence, not preference.
- [ ] Every decision carries a **REVERSIBLE / ONE-WAY** tag; every ONE-WAY
      decision was user-confirmed at the Decision Brief Gate or is marked
      UNCONFIRMED.

## Roadmap

- [ ] Milestone M0 is shippable **security/correctness** fixes, not features.
- [ ] If new functionality is built, M1 is a **walking skeleton**, not a
      layer-by-layer buildout.
- [ ] Every **UNVERIFIED** tag maps to a named **spike task**, first in the
      milestone that depends on it.
- [ ] Milestones are dependency-ordered; each has objective, entry criteria,
      effort, and exit criteria that name a runnable command or manual step.
- [ ] Every task has an ID and names concrete files/classes/migrations — no
      "improve system X".
- [ ] A risk register exists with mitigation/rollback per risk, generated by
      **pre-mortem** — no generic entries.

## Verification

- [ ] Automated verification gives exact copy-paste-runnable commands.
- [ ] Manual E2E checklist exists that a human can follow step by step.

## Goldfish gates

The elephant cannot grade its own zero-questions bar; fresh agents do.

- [ ] **G1:** a fresh goldfish explained milestones M0 and M1 task by task
      with zero guesses and zero questions, and 3 of 3 spot-checked
      citations held.
- [ ] **G2:** a fresh critic found no blocker or major issue (or each is
      fixed, or rejected with a recorded reason).
- [ ] **G3:** a fresh goldfish answered `GO` with zero questions.
- [ ] Every goldfish finding is in the ledger as `CORRECTED (goldfish)`,
      `REJECTED (goldfish)`, or `OPEN (goldfish)`, and the plan header
      states the result.

Any `OPEN (goldfish)` item is listed in the presented plan. No subagent
support: header says `Goldfish: NOT RUN` and the user is told how to run it
manually (SKILL.md, "When things go wrong").

## Rejection protocol

If the user rejects the plan, reply briefly:

> `Checklist item <N> failed acceptance — returning to Phase <X> to do the research for real.`

Then re-run that phase properly. Never argue the plan into acceptance.
